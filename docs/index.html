Why this demo

直接让大模型算化工题，问题不在“算得对不对”

而在于：你无法复核它用了什么假设、哪来的物性、中间步骤是否可信。这个 Demo 把过程和结果拆开管理。

传统“黑盒对话”

  • ✕ 模型直接给出最终数字，中间过程不可见
  • ✕ 物性参数可能被编造或混用单位
  • ✕ 无法规定“先审批、再执行”
  • ✕ 算错了只能重新提问，难以定位原因
  • ✕ 结果无法作为工程记录留存

Plan & Execute Agent

  • ✓ 先出结构化计划，逐步展示工具与参数
  • ✓ 物性、衡算、传热全部由确定性工具完成
  • ✓ 计划经人工批准后才进入执行
  • ✓ 失败只替换剩余步骤，已成功结果保留
  • ✓ 每次运行、每一步结果都落库可追溯
How it works

四步完成一次可信的化工计算

LLM 只负责“想清楚要算什么”，执行与校核交给工具和人。

01

Planner 拆解问题

读取工具目录，把自然语言问题转成 1~8 步结构化计划，明确每步工具、参数与预期产出。

02

人工审批

计划在界面中完整展开。批准后执行；不合理可填写意见驳回，Agent 重新规划。

03

Executor 执行

解析步骤间引用，校验参数，调用确定性工具。步骤失败时触发 Replanner，只替换剩余步骤。

04

Finalizer 汇总

基于实际计算结果生成报告，标注步骤来源、计算方法和假设，不复述模型猜测。

Architecture

LLM、执行器、工具三者边界清晰

LangGraph 管状态与人工审批，FastAPI 管接口，SQLite 管事实，工具层只做纯计算。

Streamlit UI → FastAPI → LangGraph → 确定性工具层 / SQLite / LLM 适配层 Plan · Approve · Execute · Replan · Report
Capabilities

为工程场景设计的六个关键能力

每一条都对应代码中的明确约束，而不是提示词里的“请务必”。

🛡️

审批中断可恢复

基于 LangGraph interrupt + SQLite checkpointer，计划生成后暂停，批准才继续；刷新页面也能恢复。

⚙️

确定性执行

执行器是纯代码：Pydantic 校验参数，只允许调用注册工具，模型不参与单步数值计算。

🔗

步骤间结果引用

支持 ${s1.density_kg_m3} 形式的引用，自动把前序结果传给后续工具，避免模型“手填中间值”。

🔁

失败自动重规划

某一步失败时，只替换剩余步骤，已成功结果保留；重规划有次数上限，防止无限循环。

📊

全过程可观测

runs / steps / events 三张表记录状态、参数、结果与事件，前端时间线可完整复盘。

🔌

模型可切换

Mock、DeepSeek、Claude 共用同一适配接口。离线演示、国内直连、海外模型都能跑。

Quick start

三分钟本地跑起来

默认使用 Mock 模式，无需配置 API Key；接入真实模型只需修改 .env。

  • 1克隆仓库并创建虚拟环境
  • 2安装 requirements.txt 依赖
  • 3运行 run_demo.py，自动打开前端
  • 4输入问题，审批计划，查看报告
TERMINAL 
# clone & install
git clone git@github.com:Huhy666/chemical-process-calculation.git
cd chemical-process-calculation
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

# run backend + frontend, then open browser
.venv/Scripts/python.exe run_demo.py
